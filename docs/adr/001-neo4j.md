# ADR 001 — Use Neo4j as the primary database

**Date:** 2026-05-31
**Status:** Accepted

## Context

Event planning data is inherently graph-shaped: users own events, events have participants, participants have relationships to each other, locations host multiple events. A relational schema would require many join tables; a graph database expresses these relationships as first-class citizens.

## Decision

Use Neo4j with Spring Data Neo4j. Domain objects are modelled as `@Node` entities; relationships (invitation, ownership, attendance) are modelled as `@RelationshipProperties` or typed relationship annotations.

## Consequences

- Queries that traverse the graph are natural and performant.
- Developers must understand Cypher query language.
- Local development requires a running Neo4j instance (Docker recommended).
- Test containers (`@DataNeo4jTest` with embedded / Testcontainers) needed for integration tests.

## Rejected alternatives

- **PostgreSQL** — join-heavy schema for the invitation/participant graph; relational model fights the domain.
- **MongoDB** — document model requires embedding or manual reference management; no native graph traversal.
